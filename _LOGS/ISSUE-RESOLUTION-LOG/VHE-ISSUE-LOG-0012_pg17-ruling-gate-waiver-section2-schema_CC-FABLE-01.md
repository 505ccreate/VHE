### Discovery — the .docx stores Word-autocorrect artifacts INSIDE its code blocks

Verified directly in `word/document.xml` of `VHE-2_THE_Work_Order_Plan_v3_7-17-2026.docx`
(not just the lossy mirror): the §2 SQL block contains **U+2018/U+2019 smart single quotes,
U+201C/U+201D smart double quotes, and U+2013 en-dashes where `--` was written**. Example run:
`kind IN (` `‘` `image` `’` … — Word autocorrect corrupted the author's straight quotes at
authoring time. A byte-verbatim copy is therefore **invalid SQL**. The corruption is mixed:
some lines (indented continuations, e.g. the `CHECK (status IN ('uploading'…))` line) kept
straight quotes; top-level paragph starts got autocorrected.

**Resolution rule (applies to every future verbatim block taken from any VHE .docx):**
copy the text from `word/document.xml`, then apply ONLY this mechanical mapping —
`U+2018/U+2019 → '` · `U+201C/U+201D → "` · `U+2013 → --` — and audit that no other
non-ASCII remains except intentional characters (e.g. `§` inside SQL comments, kept).
Nothing else may be altered. This is de-corruption, not adaptation.
